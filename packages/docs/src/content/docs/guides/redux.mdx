---
title: Use with Redux
description: Read a Redux store from React with concurrent-safe transitions.
---

Redux owns your state and you already wrote the reducer, so the React store can
fold the same actions.

## Connect the store

```ts
import { configureStore } from "@reduxjs/toolkit";
import { createStore } from "react-concurrent-store";

const redux = configureStore({ reducer: rootReducer });
const store = createStore(redux.getState(), rootReducer);

export function dispatch(action) {
  redux.dispatch(action);
  store.dispatch(action);
}
```

Both fold the same actions from the same starting state, so they stay in step.
Redux keeps your middleware and devtools; the React store handles concurrency.

## Read it in a component

```tsx
import { useStore } from "react-concurrent-store";

function Total() {
  const total = useStore(store, (state) => state.cart.total);
  return <strong>{total}</strong>;
}
```

## Selecting an object

A selector that builds a new object returns a new reference every time, so it
would re-render on every action. Compare it yourself:

```tsx
import { useStoreWithEqualityFn } from "react-concurrent-store/with-equality-fn";
import { shallowEqual } from "react-redux";

function CartSummary() {
  const { count, total } = useStoreWithEqualityFn(
    store,
    (state) => ({ count: state.cart.items.length, total: state.cart.total }),
    shallowEqual,
  );

  return <span>{count} items — {total}</span>;
}
```

## What you get

A dispatch inside `startTransition` no longer forces a synchronous re-render
the way `useSyncExternalStore` does. An urgent dispatch that lands while a
transition is still in flight applies on top of what is on screen, and when the
transition finishes both actions are reflected in the order you dispatched
them.
