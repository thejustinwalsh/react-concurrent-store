## What it is

A userland implementation of the `createStore` / `useStore` API proposed in
[React RFC #35449](https://github.com/facebook/react/issues/35449), for React 19
and up. No experimental React build required.

## What it does that a subscription cannot

An external store read with `useSyncExternalStore` cannot take part in a
transition: a store update during one opts the transition out and React flushes
it synchronously. A navigation that should have kept the old screen up drops to
a fallback instead.

`useStore` keeps the Transition the caller started, and applies a blocking
update to what is on screen rather than to a state the user cannot see yet.

```tsx
// The destination is decided. Its data has not arrived.
startTransition(() => store.dispatch({ type: "navigate", to: "/profile" }));

// Visible now, on the page they are actually looking at.
store.dispatch({ type: "like" });
```

| | screen | store |
| --- | --- | --- |
| navigating | `home/0` | `profile/0` |
| after the like | `home/1` | `profile/1` |
| after the page loads | `profile/1` | `profile/1` |

The like appears immediately, no half-loaded profile is ever shown, and the
final state has both actions in the order they were dispatched.

[Rebasing](/react-concurrent-store/explanation/rebasing/) explains how, and
the [demo](https://react-use-store.tjw.dev) shows it happening.
