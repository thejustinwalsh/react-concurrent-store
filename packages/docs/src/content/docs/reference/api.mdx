## `createStore(initialValue, reducer?)`

Creates a store. Call it outside a component, or once per mount with
`useState`.

```tsx
const counter = createStore(0);
const todos = createStore([], (state, action) => reduce(state, action));
```

### Parameters

- **`initialValue`**: the store's starting value. It may be a promise.
- **optional** **`reducer`**: `(state, action) => nextState`. Without one, an
  action is either a replacement value or an updater, `(previous) => next`,
  like the setter from `useState`.

### Returns

A store with `getState`, `dispatch` and `subscribe`.

### Caveats

- `createStore` is not a Hook, so it can be called in a Server Component —
  import it from `react-concurrent-store/store`, because the main entry also
  exports `useStore` and carries a `"use client"` directive. See
  [Server components and SSR](/react-concurrent-store/guides/server/).
- The store itself is not serializable, so it cannot be passed from a Server
  Component to a Client Component. Its value can.
- A store at module scope on a server is shared by every request.

## `useStore(store, selector?)`

Subscribes a component to a store.

```tsx
const count = useStore(counter);
const name = useStore(user, (state) => state.name);
```

### Parameters

- **`store`**: a store from `createStore`.
- **optional** **`selector`**: `(state, previous) => slice`. It receives the
  current state and its own previous result. Return that previous value and
  the render is skipped.

### Returns

The store's current value, or the selected slice.

If the value is a promise, `useStore` returns the promise — it does not unwrap
it. Pass it to `use` to suspend:

```tsx
const user = use(useStore(userStore));
```

### Caveats

- `useStore` is a Hook, so it only runs in a Client Component.
- The value a component reads is what it is allowed to show, which is not always
  what `getState()` returns. While a Transition is in flight they differ
  on purpose — see [Rebasing](/react-concurrent-store/explanation/rebasing/).
- An Effect keyed on the value runs twice when a component mounts while a
  Transition is blocked. See
  [Limitations](/react-concurrent-store/explanation/limitations/).
- There is no equality argument. See
  [Selectors and re-renders](/react-concurrent-store/explanation/selectors/).

## The store object

```tsx
type ReactConcurrentStore<S, A> = {
  getState(): S;
  dispatch(action: A): void;
  subscribe(callback: (action: A) => void): () => void;
};
```

### `dispatch(action)`

Applies an action. Whether it blocks is decided by the caller, the same way it
is for any other update:

```tsx
store.dispatch(action);                        // visible now
startTransition(() => store.dispatch(action)); // may wait
```

### `getState()`

Returns every action in dispatch order — the chronological value, which is not
necessarily what any component is showing. For reading outside React.
Components use `useStore`.

### `subscribe(callback)`

Calls `callback` after each update with the action that caused it, and returns
an unsubscribe function. The action has already been applied, so `getState()`
inside the callback includes it:

```tsx
store.subscribe(() => persist(store.getState()));
```
